## Before Using Any Library

1. Check `AGENTS.md` for installed skills (Clerk skills via `clerk skill install`, Cloudflare/shadcn skills if present).
2. If an MCP server is configured for the library (Cloudflare docs, shadcn), use it first.
3. Read this file for project rules that override general knowledge.

Order of authority: MCP server → Skills → This file → Training knowledge. Next.js, vinext, `cf`, and Clerk change often; verify against current docs. For Cloudflare use `cf docs search`, `cf cli search`, `cf schema`, or https://developers.cloudflare.com/cf/llms.txt.

## Cloudflare CLI (`cf`) and vinext

`cf` (beta) is one CLI for the Cloudflare API and for Workers projects. It has no bundler of its own: it hands `dev` and `build` to Vite. This project runs **vinext** (the Next.js 16 API reimplemented on Vite) with the Cloudflare Vite plugin 2.0 beta. Docs: https://developers.cloudflare.com/cf/ and https://github.com/cloudflare/vinext.

> Not OpenNext, not Wrangler. OpenNext builds through Wrangler and has a reported conflict with `cloudflare.config.ts` (opennextjs-cloudflare #1407). Running `cf dev/build/deploy` in a project that has a Wrangler config makes `cf` write a new `cloudflare.config.ts` that ignores that config. Do not mix the two.

### Setup

```bash
npm install --global cf          # Node.js ≥ 22.18; Bun is not supported
cf auth login                    # in CI: CLOUDFLARE_API_TOKEN + CLOUDFLARE_ACCOUNT_ID
pnpm create vinext-app@latest real-estate-tracker   # scaffold, Cloudflare target
```

- The scaffold should produce `vite.config.ts` and `cloudflare.config.ts`. If it produces `wrangler.jsonc` instead, stop: either convert with `cf migrate` or re-scaffold. Do not continue with a Wrangler config.
- For an existing Next.js app, `cf init .` detects Next.js and sets up vinext and `cloudflare.config.ts` (review the planned changes before confirming).
- `package.json` needs `"type": "module"`. Add `.cloudflare/` to `.gitignore`.
- Run `npx vinext check` to scan for known Next.js compatibility gaps.

### cloudflare.config.ts (shape)

```typescript
import { bindings, defineConfig } from "cf/config";

export default defineConfig({
  worker: {
    name: "real-estate-tracker",
    compatibilityDate: "<date written by cf init>",
    compatibilityFlags: ["nodejs_compat"],
    // entrypoint: as generated by the vinext / cf setup; don't hand-write unless setup omitted it
    env: {
      DB: bindings.d1({ name: "real-estate-tracker-db" }),
      KV: bindings.kv({ /* options: use TS completion or `cf docs search "kv binding"` */ }),
      MEDIA: bindings.r2({ /* options: as above */ }),
      CLERK_SECRET_KEY: bindings.secret(),
      GEOCODER_API_KEY: bindings.secret(),
      GEOCODER_PROVIDER: bindings.text("mapbox"),
      APP_URL: bindings.text("http://localhost:5173"),
    },
  },
});
```

- Builders: `bindings.d1 | kv | r2 | secret | text | json`. D1 options are `{ id?, name?, dev? }`. Confirm KV and R2 option names with TypeScript completion or the configuration explorer (https://developers.cloudflare.com/cf/projects/config-explorer/). Do not guess.
- `cf deploy` provisions missing resources for bindings that omit IDs and does **not** write the IDs back into the file. Local dev simulates all bindings; no IDs needed.
- `bindings.secret()` also makes `cf dev` warn about secrets missing from `.dev.vars`.
- For values that differ per environment use the function form `defineConfig(({ mode }) => ...)`. Vite accepts `--mode`; other framework commands reject it.
- Use `domains` under `worker` for custom domains.

### Reading bindings

```typescript
// lib/cloudflare.ts: the only file that imports cloudflare:workers
import { env } from "cloudflare:workers";
export function getEnv(): Env { return env; }
```

- `Env` is generated into `.cloudflare/types/index.d.ts` by the Vite plugin during `cf dev` / `cf build`, or by `cf workers types`. Add `.cloudflare/types` to tsconfig `include` explicitly (wildcards skip dot-directories).
- Call `getEnv()` inside request handlers, never at module top level.
- No `getCloudflareContext()`, no `getPlatformProxy()`, no `process.env` for bindings.

### What runs where

- `cf dev` runs the Vite dev server with the app inside workerd (Workers runtime). It prints the local URL (default `http://localhost:5173/`); `/cdn-cgi/local/explorer` opens Local Explorer to inspect bindings, logs, and traces. `cf dev` accepts no `--port`: set `server.port` in `vite.config.ts`.
- `cf build` writes Build Output to `.cloudflare/output/v0/` and needs no credentials. `cf deploy --dry-run` validates the build without credentials. `cf deploy` builds, uploads a version, and deploys. `cf previews deploy [name]` deploys a Worker Preview.
- Dev data lives in `.cloudflare/state/`. **`--local` on `cf d1/kv/r2` commands uses a different store** (`~/.config/cloudflare/state/v3` on Linux, `~/Library/Preferences/cloudflare/state/v3` on macOS), so migrations applied with `--local` may not be visible to `cf dev`. After applying migrations, check Local Explorer. If the tables are missing, try `--persist-to .cloudflare/state` (it uses `<dir>/v3`) or find the working invocation with `cf docs search` and record it in `progress-tracker.md`.

### vinext rules

- Supported and used here: App Router, React Server Components, Server Actions, route handlers, `proxy.ts`, `next/headers`, `next/navigation`, `next/cache` (`revalidatePath`, `revalidateTag`).
- Not used in v1: ISR, `revalidate`, `"use cache"` / Cache Components (incomplete in vinext), `next/image`.
- `runtime` and `preferredRegion` route config are ignored.
- `next/font/google` loads from Google's CDN at runtime (no self-hosting): the CSP must allow `fonts.googleapis.com` and `fonts.gstatic.com`.
- Never register `@vitejs/plugin-rsc` yourself: vinext does it when `app/` exists, and a duplicate fails the build. It only needs to be installed.
- Native Node modules (`sharp`, `satori`, `@napi-rs/canvas`, …) are not used.
- Run `npx vinext check` before upgrading vinext.

### Command cheat sheet

| Task | Command |
| ---- | ------- |
| Sign in | `cf auth login` |
| Find a command | `cf cli search "<task>"`, `cf <product> --help`, `cf schema <command>` |
| Search live docs | `cf docs search "<query>"` |
| Preview a request without sending it | add `--dry-run` (use IDs, not names) |
| Dev / build / validate / deploy | `cf dev` / `cf build` / `cf deploy --dry-run` / `cf deploy` |
| Deploy with secrets | `cf deploy --secrets-file <path>` |
| Worker Preview | `cf previews deploy [name]` |
| List local resources | `cf d1 list --local`, `cf kv namespaces list --local`, `cf r2 buckets list --local` |
| D1 migrations | `cf d1 migrations apply <DATABASE_ID> --local` (without `--local` it applies to **remote**) |
| D1 SQL | `cf d1 raw <DATABASE_ID> --sql "..." --local` (`cf d1 query` has no local mode) |
| KV / R2 data | `cf kv keys list\|get\|put\|delete ... --local`, `cf r2 objects list\|get\|put ... --local` |
| Generate binding types | `cf workers types` |
| DNS records | `cf dns records create --zone <ZONE_ID> --body '{...}' --dry-run`, then without `--dry-run` |

Destructive commands ask for confirmation. In non-interactive sessions they print `Aborted.` and exit `0` without changing anything: do not rely on the exit code. Read a command's `--help` before using `--force`.

## Drizzle ORM + D1

```typescript
// lib/db/index.ts
import { drizzle } from "drizzle-orm/d1";
import * as schema from "./schema";
import { getEnv } from "@/lib/cloudflare";

export function getDb() {
  return drizzle(getEnv().DB, { schema });
}
```

```typescript
// lib/db/schema.ts (excerpt)
import { sqliteTable, text, integer, real, index } from "drizzle-orm/sqlite-core";

export const properties = sqliteTable("properties", {
  id: text("id").primaryKey(),
  ownerId: text("owner_id").notNull(), // Clerk user ID, no FK
  addressLine1: text("address_line_1").notNull(),
  priceCents: integer("price_cents").notNull(),
  bathrooms: real("bathrooms").notNull(),
  status: text("status", { enum: ["draft", "active", "sold", "off_market"] }).notNull().default("draft"),
  createdAt: integer("created_at", { mode: "timestamp_ms" }).notNull().$defaultFn(() => new Date()),
}, (t) => [index("properties_status_idx").on(t.status)]);
```

```typescript
// services/properties.ts: filtered read
const rows = await db.select().from(properties)
  .where(and(eq(properties.status, "active"), gte(properties.bedrooms, f.minBedrooms ?? 0)))
  .orderBy(desc(properties.createdAt))
  .limit(pageSize).offset(offset);
```

**Rules:**

- `getDb()` is called per request, inside services only.
- D1 has no interactive transactions: use `db.batch([...])` for atomic multi-statement writes.
- Foreign keys: ensure `PRAGMA foreign_keys` behavior by relying on D1's default (enabled) and `onDelete: "cascade"` for media.
- Generate migrations with `drizzle-kit generate`; apply with `cf d1 migrations apply <DATABASE_ID> [--local]` (remote by default; see the local-state note in the `cf` section).
- Free-text search uses `LIKE` on `address_line_1`, `city`, `postal_code` with escaped `%` and `_`.
- Generate IDs with `crypto.randomUUID()`.

## Cloudflare KV

```typescript
// lib/kv.ts
export async function cacheGetJson<T>(key: string): Promise<T | null> {
  try { return await getEnv().KV.get<T>(key, "json"); }
  catch (error) { console.error("[kv/cacheGetJson]", error); return null; }
}

export async function cachePutJson(key: string, value: unknown, ttlSeconds: number): Promise<void> {
  try { await getEnv().KV.put(key, JSON.stringify(value), { expirationTtl: ttlSeconds }); }
  catch (error) { console.error("[kv/cachePutJson]", error); }
}
```

```typescript
// list version
export async function getListVersion(): Promise<string> {
  return (await getEnv().KV.get("properties:list:version")) ?? "0";
}
export async function bumpListVersion(): Promise<void> {
  await getEnv().KV.put("properties:list:version", String(Date.now()));
}
```

**Rules:**

- Cache helpers swallow errors and return `null` (cache miss). KV holds no auth state in this project.
- `expirationTtl` minimum is 60 seconds. Use ≥ 60.
- KV is eventually consistent across regions: never use it for anything that must be immediately correct. Permissions come from Clerk (identity, role) and D1 (`owner_id`).
- Query hash: SHA-256 (Web Crypto) of the normalized, key-sorted filter JSON, hex-truncated to 32 chars.
- Rate limit counter: `ratelimit:{scope}:{ip}:{window}` with TTL = window.
- Rate limits apply to geocoding and media upload only, keyed by Clerk user ID.

## Cloudflare R2 (binding)

```typescript
// lib/r2.ts
export async function putMedia(key: string, body: ReadableStream | ArrayBuffer, contentType: string): Promise<void> {
  await getEnv().MEDIA.put(key, body, { httpMetadata: { contentType } });
}

export async function getMedia(key: string): Promise<R2ObjectBody | null> {
  return getEnv().MEDIA.get(key);
}

export async function deleteMedia(key: string): Promise<void> {
  await getEnv().MEDIA.delete(key);
}
```

```typescript
// app/media/[id]/route.ts: streaming response
const object = await getMedia(row.r2Key);
if (!object) return new Response("Not found", { status: 404 });
return new Response(object.body, {
  headers: {
    "Content-Type": object.httpMetadata?.contentType ?? "application/octet-stream",
    "Cache-Control": isPublic ? "public, max-age=3600" : "private, no-store",
    "X-Content-Type-Options": "nosniff",
  },
});
```

**Rules:**

- Use the **binding**, not the S3 API. No R2 access keys in the app.
- Key format is always `properties/{propertyId}/media/{mediaId}`.
- Stream bodies; never buffer files larger than needed.
- Delete the R2 object whenever the DB row is deleted, and delete all objects with prefix `properties/{id}/media/` when a property is deleted (use `list({ prefix })`).

## Clerk (`@clerk/nextjs`)

Authentication, sessions, and user identity. Set up with the Clerk CLI in build-plan feature 10.

### Setup with the CLI

```bash
clerk init              # detects Next.js, installs @clerk/nextjs, scaffolds provider, proxy, auth pages
clerk skill install     # optional: Clerk agent skills (or: npx skills add clerk/skills)
```

`clerk init` generates files for a generic Next.js app. **Review and conform them** to `architecture.md` (route groups, `proxy.ts` at the repo root, tokens, Inter font). Delete any demo UI it adds. Other useful commands: `clerk api` (Backend API client), `clerk config pull`, `clerk open <page>`.

### proxy.ts (Next.js 16)

```typescript
import { clerkMiddleware, createRouteMatcher } from "@clerk/nextjs/server";

const isProtected = createRouteMatcher([
  "/dashboard(.*)",
  "/properties/new(.*)",
  "/properties/(.*)/edit(.*)",
]);

export default clerkMiddleware(async (auth, req) => {
  if (isProtected(req)) await auth.protect();
});

export const config = {
  matcher: [
    "/((?!_next|[^?]*\\.(?:html?|css|js(?!on)|jpe?g|webp|png|gif|svg|ttf|woff2?|ico|csv|docx?|xlsx?|zip|webmanifest)).*)",
    "/(api|trpc)(.*)",
  ],
};
```

Use the matcher `clerk init` generates if it differs. Verify the protected-route patterns actually block signed-out requests.

### Roles via session token

1. Clerk Dashboard → Sessions → Customize session token: `{ "metadata": "{{user.public_metadata}}" }`.
2. Set a user's role in the Dashboard (Public metadata `{ "role": "admin" }`) or through the Backend API with `clerk api` (update-user-metadata endpoint; see `clerk api --help`).
3. Type the claims:

```typescript
// types/globals.d.ts
export {};
declare global {
  interface CustomJwtSessionClaims {
    metadata: { role?: "viewer" | "agent" | "admin" };
  }
}
```

```typescript
// lib/auth/guards.ts: fresh role for destructive actions
export async function getFreshRole(userId: string): Promise<Role> {
  const client = await clerkClient();
  const user = await client.users.getUser(userId);
  return parseRole(user.publicMetadata.role);
}
```

### Secrets and environment

- `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` is inlined at build time: it must be present in `.env.local` (or CI env) when running `cf build` / `cf deploy`.
- `CLERK_SECRET_KEY` is declared with `bindings.secret()`. Locally it goes in `.dev.vars`; for deployed environments it is uploaded with `cf deploy --secrets-file`. If Clerk cannot read it at runtime, check how vinext exposes bindings to `process.env`.
- Clerk's keyless mode may be used for the first local run; link a real Clerk application before any deploy.
- Development and production are separate Clerk instances: keys, session-token customization, and role metadata must be set up again for production.

**Rules:**

- Never write password hashing, session storage, or auth cookies. Never add a `users` table.
- `auth()` is async; call it only in server code, and only on routes covered by the `proxy.ts` matcher.
- Never trust role or user ID from the client. Derive from `auth()`.
- Session claims can be stale for up to about a minute after a role change; use `getFreshRole` before deletes.
- Do not copy Clerk profile data into D1. Read it from Clerk when needed.
- Mock `@clerk/nextjs/server` in unit tests.
- **vinext + Clerk (known issue, cloudflare/vinext#4221):** `cf dev` can crash at startup with `ReferenceError: require is not defined` from `@clerk/nextjs/dist/esm`. Production builds are reported to work. First check whether your installed Clerk and vinext versions already fix it. If not, add a dev-only Vite plugin in `vite.config.ts` that rewrites bare `require("x")` calls in `@clerk/nextjs/dist/esm` into hoisted `import * as … from "x"`. Record any workaround in `progress-tracker.md`.
- `clerk init` generates a generic Next.js setup. Do not let it add a Wrangler config or OpenNext files.

## Geocoder (default Mapbox)

```typescript
// lib/geocoder/mapbox.ts
const res = await fetch(
  `https://api.mapbox.com/search/geocode/v6/forward?q=${encodeURIComponent(query)}&limit=1&access_token=${key}`,
  { signal: AbortSignal.timeout(4000) },
);
if (!res.ok) return null;
```

**Rules:**

- Implement the `Geocoder` interface; selecting a vendor happens only in `lib/geocoder/index.ts`.
- 4 s timeout; non-2xx or timeout returns `null` after logging status only (no address).
- Always check KV `geocode:{addressHash}` first. Normalize (trim, lowercase, collapse spaces) before hashing.
- Re-geocode on update only when an address field actually changed.

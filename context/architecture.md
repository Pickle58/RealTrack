# Architecture

## Stack

| Layer      | Tool                                   | Purpose                                  |
| ---------- | -------------------------------------- | ---------------------------------------- |
| Framework  | Next.js 16 API on vinext (Vite)        | SSR, Server Actions, route handlers, `proxy.ts` |
| Runtime    | Cloudflare Workers via vinext + Cloudflare Vite plugin (2.0 beta), driven by the Cloudflare CLI (`cf`, beta) | Edge execution |
| Database   | Cloudflare D1                          | System of record                         |
| ORM        | Drizzle ORM + drizzle-kit              | Typed queries and migrations             |
| Cache      | Cloudflare KV                          | List/detail cache, geocode cache, rate limits |
| Storage    | Cloudflare R2                          | Property media                           |
| Auth       | Clerk (`@clerk/nextjs`)                | Sign-in/up, sessions, user identity, roles |
| Geocoding  | External HTTP API behind `Geocoder` interface | Address normalization + lat/lng   |
| Styling    | Tailwind v4 + shadcn/ui                | UI                                       |
| Validation | Zod                                    | Input validation at every boundary       |
| Language   | TypeScript strict                      | Throughout                               |

> **Maturity note:** `cf`, the Cloudflare Vite plugin 2.0, and vinext are all newer than the OpenNext + Wrangler path. Build-plan feature 02 includes a go/no-go spike (including Clerk). Do not silently fall back to OpenNext or Wrangler: they conflict with `cloudflare.config.ts`. If the spike fails, stop and ask.

## System Boundaries

| Folder         | Owns                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------- |
| `app/`         | Pages, layouts, route handlers. Thin: call `services/`, render. No SQL, no business rules. |
| `actions/`     | Server Actions. Parse + validate input, authorize, call `services/`, emit events, revalidate. |
| `services/`    | Business logic and all D1 / R2 / geocoding orchestration. The only place that runs queries. |
| `components/`  | UI only. No data fetching, no DB, no KV, no R2. Receives data via props.                  |
| `lib/`         | Client initialization (db, kv, r2), auth primitives, event emitters, utilities.           |
| `validations/` | Zod schemas shared by actions, route handlers, and forms.                                 |
| `types/`       | Shared TypeScript types.                                                                  |

## Data Flows

### Mutation (create property)

```
Form submit (client component)
        ↓
Server Action actions/properties.ts → createProperty
        ↓
requireUser() + role check (agent | admin)
        ↓
Zod validation
        ↓
services/geocoding.ts → KV geocode:{hash} hit? else call Geocoder → cache
        ↓
services/properties.ts → INSERT into D1 (owner_id = Clerk userId)
        ↓
lib/events.ts → emit property.created → bump list version, delete properties:{id}
        ↓
revalidatePath + redirect to /properties/[id]/edit
```

### Read (search page)

```
GET /properties?city=..&minPrice=..
        ↓
SSR page parses searchParams with Zod
        ↓
services/properties.search(filters, viewer)
        ↓
KV properties:list:{version}:{queryHash} hit? → return
        ↓ miss
D1 SELECT (anonymous viewers: status = 'active' only)
        ↓
KV put with TTL → render
```

Cached lists are only used for the **anonymous/public** view. Owner/admin views (dashboard, drafts) bypass the list cache.

### Media upload

```
File input → Server Action actions/media.ts → uploadMedia
        ↓
requireUser() + ownership check on property
        ↓
Validate mime type + size
        ↓
R2.put(properties/{propertyId}/media/{mediaId}, stream, httpMetadata)
        ↓
INSERT property_media row (compensate: R2.delete if INSERT fails)
        ↓
emit property.updated → revalidate
```

### Media read

```
<img src="/media/{mediaId}">
        ↓
app/media/[id]/route.ts → look up row + parent property in D1
        ↓
Parent active? serve to anyone. Otherwise require owner/admin session.
        ↓
R2.get(r2_key) → stream with Content-Type, Cache-Control
```

## Routes and Mutation Surface

The spec lists `GET/POST/PATCH/DELETE /api/properties`. Decision: **reads** are route handlers, **mutations** are Server Actions.

| Operation            | Mechanism                         | Auth                    |
| -------------------- | --------------------------------- | ----------------------- |
| List / search        | `GET /api/properties` + SSR page  | Public (active only)    |
| Read one             | `GET /api/properties/:id` + SSR   | Public if active, else owner/admin |
| Create               | Server Action `createProperty`    | agent, admin            |
| Update               | Server Action `updateProperty`    | owner, admin            |
| Delete               | Server Action `deleteProperty`    | owner, admin            |
| Upload / delete media| Server Actions in `actions/media.ts` | owner, admin         |
| Serve media          | `GET /media/:id`                  | See media read flow     |

## Database Schema (D1 / SQLite)

Timestamps are stored as integer Unix milliseconds. IDs are UUID text. Money is **integer cents**.

### Users

There is **no `users` table**. Identity, credentials, and sessions live in Clerk. The app stores only the Clerk user ID (`user_...`) in `properties.owner_id`. Display names or emails are read from Clerk when needed, never copied into D1.

### `properties`

| Column         | Type    | Notes                                              |
| -------------- | ------- | -------------------------------------------------- |
| id             | text    | Primary key (UUID)                                 |
| owner_id       | text    | Clerk user ID (no FK; Clerk owns users), indexed   |
| address_line_1 | text    | Required                                           |
| address_line_2 | text    | Nullable                                           |
| city           | text    | Required                                           |
| state_province | text    | Required                                           |
| postal_code    | text    | Required                                           |
| country        | text    | Default `US`                                       |
| latitude       | real    | Nullable; from geocoder                            |
| longitude      | real    | Nullable; from geocoder                            |
| bedrooms       | integer | Required, ≥ 0                                      |
| bathrooms      | real    | Required, ≥ 0, step 0.5                            |
| price_cents    | integer | Required, ≥ 0                                      |
| currency       | text    | Default `USD`                                      |
| status         | text    | `draft` \| `active` \| `sold` \| `off_market`, default `draft` |
| created_at     | integer | System-managed                                     |
| updated_at     | integer | System-managed                                     |

Indexes: `(status)`, `(owner_id)`, `(city)`, `(price_cents)`, `(bedrooms)`.

### `property_media`

| Column      | Type    | Notes                                  |
| ----------- | ------- | -------------------------------------- |
| id          | text    | Primary key (UUID)                     |
| property_id | text    | FK → properties.id, `ON DELETE CASCADE`, indexed |
| r2_key      | text    | Unique; `properties/{propertyId}/media/{id}` |
| mime_type   | text    |                                        |
| size_bytes  | integer |                                        |
| alt_text    | text    | Nullable                               |
| is_cover    | integer | 0/1, at most one per property          |
| uploaded_at | integer | System-managed                         |

## Storage

| Bucket                | Path                                       | Contents                          |
| --------------------- | ------------------------------------------ | --------------------------------- |
| `MEDIA` (R2 binding)  | `properties/{propertyId}/media/{mediaId}`  | Photos, floor plans, documents    |

Bucket is **private**. No public bucket URL, no guessable keys leave the server. All reads go through `/media/[id]`.

### KV keys (`KV` binding)

| Key pattern                               | Value             | TTL        |
| ----------------------------------------- | ----------------- | ---------- |
| `properties:list:{version}:{queryHash}`   | JSON page of results | 60 s    |
| `properties:list:version`                 | integer counter   | none       |
| `properties:{id}`                         | JSON property + media | 300 s  |
| `geocode:{addressHash}`                   | JSON `{lat,lng,normalized}` | 30 days |
| `ratelimit:{scope}:{userId}:{window}`     | integer counter   | = window   |

List invalidation uses a version counter: events increment `properties:list:version`, which orphans all older list keys (they expire by TTL). This avoids prefix scans in KV.

## Authentication

- Provider: **Clerk** (`@clerk/nextjs`). Prebuilt `<SignIn />` and `<SignUp />` components. Sign-in methods (email + password to start, social optional) are toggled in the Clerk Dashboard, not coded.
- Identity: the Clerk user ID is the only user identifier the app stores. No users table, no password handling, no session storage in D1 or KV.
- Roles: `viewer` / `agent` / `admin`, stored in Clerk `publicMetadata.role` and exposed to the server by customizing the session token to include `{ "metadata": "{{user.public_metadata}}" }`. A user with no role is treated as `agent`. Admins are promoted in the Clerk Dashboard (or with `clerk api`).
- Server access: `auth()` from `@clerk/nextjs/server`, wrapped by `lib/auth/guards.ts` (`getOptionalUser`, `requireUser`, `requirePageUser`, `getFreshRole`).
- `proxy.ts` runs `clerkMiddleware` and calls `auth.protect()` for protected routes. It is a convenience layer: **authorization is always re-checked inside each Server Action and service**.
- Session token claims can lag a role change by up to about a minute. Destructive actions (delete) read the role fresh through Clerk's backend client.
- Protected routes: `/dashboard`, `/properties/new`, `/properties/[id]/edit`, and every Server Action.
- Public routes: `/`, `/properties`, `/properties/[id]` (active only), `/sign-in`, `/sign-up`, `/media/[id]` (active parents only), `GET /api/properties*`.
- After sign-in: return to the originally requested page, else `/dashboard`. After sign-out: `/`.
- Clerk development and production are separate instances with separate users, keys, token customization, and role metadata.

## Geocoding Pattern

```typescript
// lib/geocoder/types.ts
export interface Geocoder {
  geocode(address: AddressInput): Promise<GeocodeResult | null>;
}
// services/geocoding.ts: hash address → KV get → provider call → KV put (30d) → return
```

Called server-side only; API key from a Worker secret. Failure or rate limit returns `null`, the property still saves, and `latitude/longitude` stay null.

## Failure Behavior

| Dependency down   | Behavior                                                                    |
| ----------------- | --------------------------------------------------------------------------- |
| D1                | Read and write pages show a friendly error page; no partial render          |
| KV                | Cache reads treated as misses (go to D1); rate-limit checks fail open; auth is unaffected |
| Clerk             | Sign-in and sign-up fail. Public browsing keeps working. Already signed-in users keep working until their session token expires |
| R2                | Listings render without images (placeholder); uploads return a readable error |
| Geocoder          | Property saves without coordinates; "Location not verified" indicator       |
| Partial write     | Media insert failure deletes the R2 object; R2 delete failure is logged and the DB row is still removed (orphan cleanup noted in tracker) |

## Invariants

Rules the AI agent must never violate:

- Components contain no data fetching, DB, KV, or R2 logic. `app/` pages call `services/` only.
- Every Server Action starts with `requireUser()` (Clerk handles sign-in and sign-up) and an explicit ownership or role check. Never trust a `propertyId` from the client without checking `owner_id`.
- Anonymous or non-owner queries must filter `status = 'active'`. Draft, sold, and off-market properties are visible only to owner/admin.
- All D1 access uses Drizzle's parameterized builders. Never concatenate SQL strings.
- Every KV `put` for cache or geocode data sets a TTL. Only `properties:list:version` has none.
- Every mutation that changes a property calls the matching event emitter from `lib/events.ts`. Never delete KV keys inline in actions.
- API keys and secrets exist only in Worker secrets / `.dev.vars`. Nothing secret uses a `NEXT_PUBLIC_` prefix. (`NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` is public by design; `CLERK_SECRET_KEY` is not.)
- Cloudflare configuration lives only in `cloudflare.config.ts`, managed with `cf`. Never create `wrangler.jsonc` / `wrangler.toml`, never run `wrangler`, and never add OpenNext (`@opennextjs/cloudflare`) to this project.
- Bindings are read only through `getEnv()` in `lib/cloudflare.ts` (backed by `cloudflare:workers`). Nothing else imports `cloudflare:workers`.
- No ISR, `revalidate`, or `"use cache"` in v1: pages render dynamically, and freshness comes from the KV version counter.
- R2 keys are generated by the server (UUID). User-supplied filenames never form part of a key.
- Never write password, session, or auth-cookie code. Clerk owns all of it. Session tokens never appear in logs or cached values.
- Role and user ID always come from `auth()` / Clerk, never from form fields, query strings, or request bodies.
- No hardcoded hex colors or raw Tailwind color classes in components — use tokens from `ui-tokens.md`.
